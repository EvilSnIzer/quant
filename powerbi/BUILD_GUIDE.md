# Power BI Report — Build Guide

This guide builds the three-page **Portfolio Risk & Regime Dashboard** from the
CSVs in [`data/processed/powerbi/`](../data/processed/powerbi/). Every measure
referenced here is defined (with commentary) in
[`measures.dax`](measures.dax) — copy each block into the model via
**Modeling > New measure**.

For a visual walkthrough before opening Power BI, open the self-contained
[virtual dashboard preview](dashboard_mockup.html). It mirrors the three pages,
uses the repository's current chart exhibits, and includes clickable page
navigation plus a regime-scope selector. The full KPI definitions, formulas,
source columns and interpretation rules are in the [KPI catalog](KPI_CATALOG.md).

Approximate build time: 60–90 minutes.

---

## 1. Get data

Power BI Desktop → **Get Data > Text/CSV**, one import per file (or Get Data >
Folder to pick up all files at once):

| File | Grain | Role |
|---|---|---|
| `dim_date.csv` | date | Calendar dimension |
| `dim_asset.csv` | ticker | Asset dimension (name, class, sector) |
| `fact_returns.csv` | date × ticker | Fact: returns, rolling vol, drawdown, VaR, breach flags |
| `portfolio_daily.csv` | date | Portfolio/benchmark/macro/regime daily series |
| `corr_long.csv` | scope × asset pair | Correlation matrices (full sample + per regime) |
| `regime_episodes.csv` | episode | Contiguous regime spells |
| `regime_summary.csv` | regime | Per-regime aggregates |
| `risk_summary.csv` | asset | Per-asset summary (KPI/table) |

**Power Query clean-up** (applies to all tables):
- Confirm `date` columns are type **Date** (not Text).
- `fact_returns[breach95]` / `breach99` and `portfolio_daily[port_breach95/99]`
  are 1/0 integers — keep as whole numbers.
- Returns, vols, VaR, drawdown, correlations are decimals (fractions, e.g.
  `0.021` = 2.1%). Leave as-is; format in the model as percentages.

## 2. Model

Create relationships (Model view, drag between columns):

| From (one) | To (many) | Active |
|---|---|---|
| `dim_date[date]` | `fact_returns[date]` | ✔ |
| `dim_date[date]` | `portfolio_daily[date]` | ✔ |
| `dim_asset[ticker]` | `fact_returns[ticker]` | ✔ |

- `corr_long`, `regime_episodes`, `regime_summary`, `risk_summary` stay
  **disconnected** (their slicers/filters work through measures or their own
  columns — this is intentional).
- Select `dim_date` → **Table tools > Mark as date table**.
- Hide columns you won't use on canvases (keys, redundant dates on fact tables).
- Create all measures from `measures.dax`. Set default format: **Percentage,
  1 decimal** for `%` measures; **Whole number** for day/breach counts.

> **Refreshing later:** the CSVs are regenerated by the pipeline (GitHub
> Actions or `python scripts/run steps 01→05`). In Power BI hit
> **Refresh** — no model changes needed. If you used Folder import, new
> dates flow in automatically.

## 3. Page 1 — Portfolio Overview

**Goal:** where are we, how bad has it been, and is risk elevated now?

Layout: top row of KPI cards, two charts, one table.

1. **KPI cards** (Insert > Card, or a row of 6 "new" cards):
   - `[Current VaR 95 %]` — subtitle: "1-day, trailing 250d (historical)"
   - `[Current 30D Vol %]`
   - `[Current Drawdown %]`
   - `[Max Drawdown %]`
   - `[Current Regime]` (add detail: `[Days in Current Regime]` days)
   - `[Portfolio VaR Breach Rate 95 %]` — add a reference: expected 5.0%
2. **Cumulative performance** — Line chart:
   - X: `dim_date[date]` (continuous), Y: `portfolio_daily[port_index]`,
     `portfolio_daily[qqq_index]`, `portfolio_daily[spy_index]`
   - Rename legend entries via the fields well ("Portfolio", "QQQ", "SPY").
3. **Drawdown** — Area chart: X `date`, Y `portfolio_daily[port_drawdown]`.
   Set Y axis min to a round floor (e.g. -0.6) and format as %.
4. **Risk table** — Table visual from `risk_summary`:
   `ticker`, `asset_class`, `cagr`, `ann_vol`, `var95_current`, `max_drawdown`,
   `worst_day`. Add conditional formatting: data bars on `ann_vol`, red scale
   on `max_drawdown`.
5. **Slicers**: `dim_date[date]` (between), `dim_asset[asset_class]`,
   `dim_asset[sector]`. Note: asset slicers only affect the fact/summary
   visuals, not the portfolio series (it's precomputed — that's intended).

**DAX on this page:** `Current VaR 95 %`, `Current 30D Vol %`,
`Max Drawdown %`, `Portfolio VaR Breach Rate 95 %`, `Rolling 30D Avg Daily
Return %` (optional tooltip), `Worst Day %`.

## 4. Page 2 — Correlation & Diversification

**Goal:** show correlations shifting between regimes — the diversification
argument in one view.

1. **Correlation heatmap** — Matrix visual:
   - Rows: `corr_long[asset1]`; Columns: `corr_long[asset2]`;
     Values: `[Correlation]` (= `MAX(corr_long[correlation])`)
   - **Conditional formatting** (Cells > Background):
     style "Rules" or "Gradient" based on `[Correlation]`, minimum **-1**
     (blue) → maximum **1** (red) — fixed anchors keep the colors comparable
     across regimes.
   - Turn off row/column subtotals and totals (both axes) — a diagonal of 1s
     adds nothing.
2. **Regime slicer** — Slicer on `corr_long[scope]` (values: *Full sample*,
   *Low*, *Normal*, *Elevated*, *Crisis*). Single-select recommended.
   This filters the matrix — the whole point of the page: flip between
   *Low* and *Crisis* and watch the matrix warm up.
3. **Correlation over time** — Line chart: X `date`,
   Y `portfolio_daily[avg_pairwise_corr]`, `portfolio_daily[avg_corr_cross]`
   (label: "Equity–crypto"). Add a horizontal constant at 0.5 (analytics
   line via a measure like `Reference 0.5 = 0.5`).
4. **Correlation by regime** — Clustered bar chart: X
   `regime_summary[regime_name]`, Y `avg_pairwise_corr` and `avg_vix`
   (or use `[Calm Regime Avg Corr]` / `[Corr Now vs Calm Regime]` KPIs).
5. **KPI card** — `[Pairs Above 0.70]` (respects the scope slicer).

> **Why a disconnected `corr_long`?** Pairwise correlations can't be computed
> in a matrix visual from raw returns in DAX at this scale. The pipeline
> precomputes them per regime; the slicer simply selects the matrix.

## 5. Page 3 — Regime Timeline

**Goal:** a market-history chart with regime bands, plus regime statistics.

1. **Regime bands + benchmark** — Combo chart (Clustered column + Line):
   - X: `portfolio_daily[date]`, axis type **Categorical** (with "Show items
     with no data" off) — or Continuous if columns render thin enough.
   - Column y-axis: `portfolio_daily[regime_constant]` … the column trick:
     create a calculated column `regime_constant = 1` in `portfolio_daily`,
     use it as the column value, and put
     `portfolio_daily[regime_name_smoothed]` in the **Legend**. Each day
     renders as a column colored by regime.
   - Line y-axis: `portfolio_daily[qqq_index]` (secondary axis) — the
     benchmark overlaid on the bands.
   - Set column gap width to 0 so bands look continuous.
   - *Alternative:* if you prefer visuals over tricks, use the line chart
     with a **discrete** colored band via small multiples on
     `regime_name_smoothed`, or simply export
     `reports/charts/vol_regime_timeline.png` as an image tile.
2. **Volatility line** — Line chart: X `date`, Y `portfolio_daily[port_vol30]`
   (and `port_vol90` if you like), formatted as %.
3. **Episode table** — Table from `regime_episodes`:
   `regime_name`, `start_date`, `end_date`, `n_days`. Sort by `start_date`.
4. **Regime stats cards** — `[Avg Episode Duration (days)]`,
   `[Max Episode Duration (days)]`, `[Episode Count]`, sliced by a
   `regime_episodes[regime_name]` slicer.
5. **Macro panel** (optional) — Line chart: X `date`,
   Y `portfolio_daily[VIXCLS]`; add `DGS10` on a secondary axis.
   KPIs: `[VIX Current]`, `[10Y Yield Current]`.

**DAX on this page:** `Current Regime`, `Days in Current Regime`,
`Avg/Max Episode Duration (days)`, `% of Days in Regime`,
`Avg 30D Vol in Regime %`, `Worst Day in Regime %`.

## 6. Polish checklist

- **Theme:** dark navy headers (#1A2744), red accents (#B02A30), consistent
  10pt font; page titles with the "Text box" + horizontal rule.
- **Tooltips:** add `[Rolling 30D Avg Daily Return %]` and `[Worst Day %]` to
  the line chart tooltip fields.
- **Bookmarks:** on Page 2, save one bookmark per regime scope
  (*Low* / *Crisis*) and add two buttons — a nice demo flow.
- **Performance:** all heavy computation is precomputed in Python; the model
  is import-mode and small (~15k fact rows), so interactions are instant.

## 7. Publish

Home > Publish to your Power BI Service workspace. For scheduled refresh of
the *data*, the CSVs are regenerated by the repo's GitHub Actions pipeline;
either re-publish the file, or push the CSVs to a location your gateway can
reach (OneDrive/SharePoint) and schedule refresh there.
